# حماية قاعدة بيانات الإنتاج

طبّق الترحيلات بترتيبها. الترحيل 20261015234112 يجهّز التحقق بالبريد، و20261015235949 يفعّله ويغلق الاستثناءات العامة السابقة. لا تعِد تطبيق citizen-services.sql وحده بعد التفعيل؛ فهو يوثق مرحلة سابقة. استخدم verify-staff-access.sql وverify-citizen-email-otp.sql للتحقق داخل معاملات ملغاة: 24 اختبار صلاحيات و20 اختبار تحقق. verify-production.sql يوثق الإصدار الأول فقط.

- المواطن يؤكد بريده برمز صالح 5 دقائق، ثم يحصل على إذن مؤقت لعملية واحدة. وظائف Pages تستدعي دوال السيرفر الخاصة بعد التحقق. لا يوجد إذن INSERT أو SELECT أو UPDATE أو DELETE مباشر للزائر على جداول public.
- الاستعلام يشترط مطابقة البريد المؤكد والاسم والرقم القومي والهاتف، ولا يعيد صورًا أو حسابات موظفين. حاجز PostgREST يرفض كل مسارات الزائر المباشرة. دوال المواطن القديمة متاحة للموظف بصلاحياته وسياسات RLS فقط.
- الموظف يحتاج سجل staff نشطًا وجلسة auth.sessions مرتبطة بالـJWT؛ VIEWER للقراءة فقط، والكتابة ADMIN/SUPER، والحذف SUPER.
- قراءة الصور الخاصة للموظف النشط. صور المواطن تُجهّز إلى JPEG وتُرفع عبر السيرفر إلى images/citizen/<verification-id>/؛ ست صور كحد أقصى، 1200×1200 و1.5MiB للصورة. توجد حدود يومية وللمساحة وتنظيف للرفع المهجور. الرفع والقراءة والحذف المباشر للزائر ممنوع.
- أُغلقت دوال الصيانة القديمة وغير المستخدمة عن العملاء. تبقى أربع دوال SECURITY DEFINER مقصودة: التحقق من الدور وإنشاء وحذف الموظفين وربط البريد القديم بواسطة SUPER. دوال التحقق الجديدة SECURITY INVOKER ومتاحة لـservice_role فقط، مع RLS مغلق على جداول الرموز الخاصة.
- كلمات مرور الموظفين الجدد 12 خانة وحروف كبيرة وصغيرة وأرقام. تسجيل الدخول محمي بـTurnstile على السيرفر، وإنشاء الحسابات العامة معطل.
- orders هو جدول المركبات، والمعرف UUID والتواريخ bigint بالميلي ثانية. assign_vehicle_code يحجز الكود ذريًا ويمنع التكرار الجديد. تعارض 1960 التاريخي على سجلين محفوظ دون إعادة ترقيم.
