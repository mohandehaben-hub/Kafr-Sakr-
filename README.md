# منظومة تقنين المركبات — كفر صقر

واجهة HTML وJavaScript لخدمات المواطنين ولوحة الموظفين، متصلة بـ Supabase.

خدمات المواطنين لا تحتاج حساب موظف، وتحتاج تأكيد البريد برمز OTP قبل كل تقديم أو شكوى أو استعلام. الطلب مرتبط بالبريد المؤكد، والاستعلام يحتاج نفس البريد والاسم والرقم القومي والهاتف. الطلبات القديمة تحتاج ربط البريد بواسطة SUPER بعد التحقق من الهوية. قراءة بيانات الإدارة والتعديل والحذف والتكويد تتطلب موظفًا نشطًا وصلاحية مناسبة. Cloudflare Turnstile مطلوب للدخول وطلب رمز المواطن، والتحقق يُفرض على السيرفر. راجع [إعداد التحقق بالبريد وحدود الخدمة المجانية](docs/CITIZEN-EMAIL-OTP.md).

## التشغيل والتحقق

تحتاج Node.js 22 أو أحدث. الأوامر:

```text
npm ci
npx playwright install chromium
npm run check
npm test
npm audit
npm run build
```

على Windows تستعمل الاختبارات Microsoft Edge المثبت، وعلى Linux تستعمل Chromium الخاص بـ Playwright. لا تستخدم الاختبارات بيانات حقيقية؛ جميع طلباتها معزولة ببدائل محلية.

## النشر

انشر أصول `dist/` مع وظائف Cloudflare Pages في `functions/` باستخدام أداة Pages الرسمية من جذر المستودع. يلزم إعداد متغيرات السيرفر السرية الموضحة في دليل التحقق. لا تنشر مجلد المشروع كله؛ البناء يستبعد `audit/` و`database/` و`tests/` وملفات البيئة. رفع الملفات الثابتة وحدها لا يشغّل إرسال رموز التحقق.

`_headers` مخصص للاستضافة التي تدعم صيغة Cloudflare Pages. يجب التحقق من ظهور ترويساته على الاستجابة بعد النشر؛ وجود الملف محليًا لا يغير الموقع الحالي. سير عمل verify يفحص المشروع، ولا ينشره.

سكربتات المكتبات مستضافة محليًا في `vendor/`: Supabase JS 2.107.0 وSheetJS CE 0.20.3. النسخة الأخيرة مصدرها [توزيع SheetJS الرسمي](https://docs.sheetjs.com/docs/getting-started/installation/). عند ترقية تبعية، حدّث ملفات vendor المطابقة ورخصها، وأعد الاختبارات والبناء.

## متطلبات قاعدة البيانات

- كل موظف، بما فيه المدير الرئيسي، يحتاج سجلًا صحيحًا في `staff` مرتبطًا بـ Auth user_id، ودورًا من SUPER أو ADMIN أو VIEWER. لا يوجد استثناء يعتمد على اسم المستخدم أو البريد.
- التكويد الآمن يحتاج الدالة والقيد الموضحين في [تعليمات قاعدة البيانات](database/README.md). طُبقت الدالة وسجل الحجوزات على المخطط الفعلي مع اختبارات الصلاحيات والتزامن. يوجد تعارض تاريخي واحد محفوظ للكود 1960، ولا تقبل الدالة إنشاء تعارضات جديدة.
- يجب فرض الصلاحيات والتحقق من المدخلات والحدود في RLS ودوال السيرفر؛ فحوص الواجهة لا تحل محلها.
- «تصدير الطلبات والشكاوى» ملف بيانات، وليس نسخة استعادة كاملة لقاعدة البيانات أو صور Storage أو حسابات Auth.

حالة الإصلاحات والتحقق من الإنتاج في [سجل التغييرات الأمنية](docs/SECURITY-CHANGES.md). ملفات المراجعة والنسخ الاحتياطية المحلية مستبعدة من المستودع والنشر.
