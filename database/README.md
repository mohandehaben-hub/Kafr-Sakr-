# حماية قاعدة بيانات الإنتاج

طبّق الترحيلات بترتيبها؛ الحالة الحالية تجمع تقليل الصلاحيات في 20261015215545 والاستثناءات المقيدة لخدمات المواطنين في 20261015220546. استخدم verify-staff-access.sql للتحقق داخل معاملة ملغاة؛ نجح 19 اختبارًا حيًا. verify-production.sql يوثق اختبار الإصدار الأول فقط.

- المواطن يستطيع إنشاء طلب أو شكوى بحالة pending فقط. التريجر يمنع اختيار الكود أو الرد أو الحالة الإدارية. لا يوجد إذن SELECT مباشر أو UPDATE أو DELETE له على جداول public.
- أربع دوال فقط متاحة للمواطن: get_my_order وget_my_complaints وcheck_nid_available وcan_submit_complaint. الاستعلام يشترط مطابقة الاسم والرقم القومي والهاتف، ولا يعيد صورًا أو حسابات موظفين. حاجز PostgREST يسمح فقط بمسارات الخدمات المحددة وPOST للزائر.
- الموظف يحتاج سجل staff نشطًا وجلسة auth.sessions مرتبطة بالـJWT؛ VIEWER للقراءة فقط، والكتابة ADMIN/SUPER، والحذف SUPER.
- قراءة الصور الخاصة للموظف النشط. رفع المواطن إلى images/ فقط، بحد 5MB وأنواع JPEG/PNG/WebP؛ لا يستطيع قراءتها أو استبدالها أو حذفها. Storage له سياسات مستقلة عن حاجز REST.
- أُغلقت دوال الصيانة القديمة وغير المستخدمة عن العملاء. تبقى سبع دوال SECURITY DEFINER مقصودة: أربع لخدمات المواطن المحدودة وثلاث للتحقق من الدور وإدارة الموظفين.
- كلمات مرور الموظفين الجدد 12 خانة وحروف كبيرة وصغيرة وأرقام. تسجيل الدخول محمي بـTurnstile على السيرفر، وإنشاء الحسابات العامة معطل.
- orders هو جدول المركبات، والمعرف UUID والتواريخ bigint بالميلي ثانية. assign_vehicle_code يحجز الكود ذريًا ويمنع التكرار الجديد. تعارض 1960 التاريخي على سجلين محفوظ دون إعادة ترقيم.
